🤖 Cấu hình Model Mappings (Models Settings)

Tùy biến tên mô hình được ánh xạ cho 4 phân cấp (Tiers) khi Codex gửi request qua Jev Router.

Dành cho git status, format, sửa typo, tác vụ đơn giản
Dành cho 1-2 file, code theo plan có sẵn, unit test
Dành cho đa module, bug phức tạp, feature planning
Dành cho kiến trúc hệ thống, data migration, security
Sử dụng khi Jev API không phản hồi hoặc không nhận diện được
Địa chỉ của proxy gateway phía sau (cli-proxy-api)
Khóa Bearer Token xác thực kết nối CLIProxyAPI (đồng bộ /v1/models)
Model chịu trách nhiệm phân loại tier & reasoning effort
Khóa API OpenRouter để gọi Jev Model. Để trống để giữ nguyên.

🔀 Cấu hình Quy tắc định tuyến (Routing Rules)

Bật/tắt các hành vi tự động và quản lý bộ từ khóa nhận diện lập kế hoạch (Planning) & kiến trúc (Architecture).

⚡ Bật Model Rewriting (Định tuyến thông minh)
Tự động viết lại trường model và reasoning.effort trong request gửi tới Codex gateway. Tắt tính năng này để chuyển tiếp nguyên bản (Bypass).
🎯 Bật Planning Priority Boost (Ưu tiên Lập kế hoạch)
Tự động ưu tiên chọn tối thiểu SOL (hoặc ASTRA nếu là kiến trúc) kèm mức suy luận HIGH mỗi khi phát hiện task Planning / Superpowers.
🚀 Bật Auto-Escalation khi Tool lỗi
Tự động nâng tier model cao hơn khi các lệnh hoặc tool call gặp lỗi liên tiếp (error streak).
Khoảng cách thời gian tối thiểu giữa 2 lần kích hoạt leo thang do lỗi tool.
Khi prompt chứa bất kỳ từ khóa nào trong danh sách này, router sẽ tự động ưu tiên gán Sol/Astra và Reasoning High.
Các từ khóa kiến trúc đặc thù (microservices, concurrency, migration...) sẽ kích hoạt nâng thẳng lên ASTRA.

⚡ Cấu hình Tối ưu hóa Prompt (Prompt Optimizer Settings)

Tự động tiền xử lý, cấu trúc hóa và làm rõ prompt của người dùng TRƯỚC KHI gửi tới Jev để phân loại và Codex để sinh code.

⚡ Bật Prompt Optimizer trước khi gửi Jev & Codex
Tự động lọc các câu hỏi con người, làm rõ yêu cầu, bổ sung cấu trúc đầu ra mà vẫn giữ nguyên 100% mục tiêu kỹ thuật.
API tương thích OpenAI (mặc định CLI Proxy API: http://127.0.0.1:8317/v1/chat/completions)
Mô hình tối ưu hóa prompt (mặc định: gemini-3.8-flash-high)
Nếu để trống và trỏ tới CLI Proxy API sẽ tự dùng Upstream API Key
Hết thời gian này sẽ tự động bỏ qua (zero-latency fallback)
Giới hạn token (cần thiết với OpenRouter flash models)
Độ sáng tạo thấp giúp prompt chính xác và bám sát thực tế
Bỏ qua các câu quá ngắn dưới ngưỡng này
Bỏ qua câu có ít hơn số từ quy định
🔒 Bảo toàn nghiêm ngặt Biến số (Strict Variable Preservation)
Hủy bỏ tối ưu và giữ nguyên bản nếu phát hiện biến số {{var}} hoặc ${var} bị thay đổi hoặc thiếu.
⏭️ Tự động bỏ qua các câu xác nhận ngắn (Skip Short Confirmations)
Không kích hoạt optimizer khi người dùng chỉ gõ yes, ok, tiếp tục, chạy đi, v.v.
Nếu prompt chứa các từ này, hệ thống sẽ bỏ qua để không can thiệp vào vòng lặp agent ngầm.
Hướng dẫn chỉ đạo mô hình optimizer cách tinh chỉnh văn bản mà không làm sai lệch ý định của lập trình viên.
